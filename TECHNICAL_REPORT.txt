PROVIDER CONTRACT AND REQUEST FLOW
Adapters declare vision, OCR, translation and region capabilities and supply
request URL, headers, body and response extraction. analyze() performs joint
OCR/translation/region analysis and returns a common validated representation:
{x, y, width, height, source, text, background}, coordinates normalized 0-1000.
Unsupported functions such as neural inpainting and dedicated OCR are not
advertised as provider capabilities. No separate OCR key/provider is necessary.

Flow: select image -> obtain public settings -> check key/model readiness in
worker -> extract image locally or retrieve source -> decode and downscale ->
split long images into overlapping tiles -> send tiles sequentially to the
selected vision API -> validate JSON -> map regions to image coordinates ->
deduplicate overlapping regions -> fill regions and fit translated text locally.
Source pixels remain unchanged in the webpage; the visual overlay is removable.
Page processing uses the same pipeline sequentially for loaded images/canvases.
An API error stops that page job with a visible message. There are no automatic
paid retries. Restore discards pending overlays. Stop aborts the active request
and cancels remaining images; the overlay stays visible while a request runs.
Cancellation closes the extension's request; a provider may still process or
charge for work it already received.

LOCAL STORAGE
chrome.storage.local contains one config object:
provider, endpoint, apiKey, model, source, target, quality, instructions,
detectSfx, cleanup, font, fontScale, tileSize, minImageSize, requestTimeout.
requestTimeout is seconds (0 = automatic). Automatic uses 240 seconds for model
IDs containing gemma-4-31b-it and 90 seconds otherwise. Explicit limits are
bounded to 30-240 seconds. Gemma uses tiles up to 1000 pixels, respecting smaller
user settings, and streaming on the Gemini and compatible adapters.
Storage is restricted to TRUSTED_CONTEXTS. Content scripts receive a public
projection without apiKey or endpoint. Save/read/delete/test are restricted to
the extension's popup/settings URLs. Keys are not put in URL parameters, image
requests, logs, exported images or page messages. Keys are not encrypted at rest.
Only one selected provider/key/model is saved at a time. Switching provider or
editing the endpoint clears the key field before saving. Translation results
are held in page memory, not a persistent cache. Reloading removes them.

ALL REMAINING NETWORK REQUESTS
1. POST <configured base URL>/chat/completions for OpenAI-compatible providers.
   Default base: https://api.openai.com/v1. Sends selected model, instructions,
   language preferences and image tile, with API key in Authorization header.
2. POST https://generativelanguage.googleapis.com/v1beta/models/<model>:generateContent
   for Gemini. Sends image/text and the key via x-goog-api-key. Gemma uses
   :streamGenerateContent?alt=sse on the same host instead. The SSE reader handles
   fragmented events and UTF-8, skips thought parts, and remains cancellable.
3. POST https://api.anthropic.com/v1/messages for Anthropic. Sends image/text,
   model, response length setting and key via x-api-key.
Only the selected adapter runs. A connection test sends a short text prompt
through that same adapter. Provider redirects are rejected, and cookies omitted.
4. GET the selected image's existing HTTP(S) source when local canvas extraction
   is unavailable. No provider key or cookies accompany this request. Source
   image redirects are allowed; image servers may reject hotlink requests.
5. Local data URLs and packaged font/resource reads are not external traffic.
No telemetry, reporting, IP lookup, Tori service or remotely loaded code remains.
Broad HTTP(S) host access supports arbitrary manga sites and user endpoints.
There is no request-header rewriting or injected MAIN-world code.

ERRORS AND LIMITS
Explicit errors cover missing key/model, denied/invalid key, quota exhaustion,
rate limiting, unsupported model/request/endpoint, network/timeout, malformed
responses, OCR refusal/empty output, inaccessible images and invalid geometry.
No text detected is a valid OCR result. Provider response text is never rendered
as HTML. Inputs and translations are rendered via canvas/textContent/form values.
Images are limited to 16 MB downloaded bytes, 32 million working pixels and
32760 working rows. Tiles are 600-2000 pixels with 100-pixel overlap. The default
working width is at most 1400 pixels. PNG exports use that working resolution.
Requests time out rather than retrying indefinitely. The browser's MV3 worker
lifecycle can interrupt slow provider responses; this has not been live-tested.

REPLACED OR UNSUPPORTED ORIGINAL FUNCTIONALITY
Vision-estimated text regions replace the private OCR/text/bubble detector.
Coordinates and OCR accuracy depend on the chosen model and may need correction.
Solid background rectangles replace neural inpainting; textured art is not
reconstructed. Tile boundaries can still split dialogue despite overlap.
The lightweight editor supports translation text and rectangular geometry;
original warps, brushes, custom font management, precise bubble masks, cached
translations, automatic translation, screenshots/crop, PDF/ZIP export and
original multilingual interface are not carried over.
Loaded IMG and readable CANVAS elements are supported in the top-level document.
CSS background images, closed shadow trees, embedded frames, browser-protected
pages and unloaded lazy images are not scanned. Scroll to load pages first.
Fixed overlays follow normal image positioning and object-fit, but complex CSS
transforms, ancestor clipping, padding/borders or unusual stacking may misalign.
Fonts fall back to system glyphs where the bundled fonts lack a script.
Only Chromium packaging is provided; Firefox and Safari are not verified.

TEST RESULTS
All 23 automated tests passed; JavaScript syntax and resource checks passed.
OCR requests now include an explicit JSON-only output contract: exact fields,
coordinate bounds, escaped strings, no Markdown or explanation, and task
preferences encoded separately as JSON data. The contract stays in the image
request for Gemma compatibility; no unverified system-role, thinking-control,
or structured-output API parameters were added. This improves instructions but
does not guarantee model compliance or reduce internal reasoning.
Additional checks cover streamed Gemini OCR, compatible streaming, JSON fallback,
split UTF-8, cancellation during stalled streams, slow-model defaults, and
separate extension/provider timeout messages. No live Gemma call was performed.
Cancellation tests cover each adapter, response-body reads, image downloads,
tab isolation, requests waiting for settings and restarting after cancellation.
OCR parsing also accepts numeric strings, missing source transcription, named
bounding boxes, consistent fractional coordinates and explicit percentages.
Small edge overshoots are clipped; unusable boxes still produce specific errors.
Automated Node tests validate initial settings, missing keys/models, public
secret projection, endpoint validation, each provider's image request/response,
language/model changes, API error categories, malformed OCR/coordinate rejection,
tile overlap deduplication, wrapping/positioning, cleanup setting, installation
handler defaults, storage persistence across simulated worker reload, key deletion,

These tests mock browser storage, image decoding, canvas and API responses.
Syntax checks cover all JavaScript files. Manifest/resource paths are checked.
Source scan found no legacy Tori/account/credit dependencies in runtime code.
The only broad keyword matches in runtime code are Authorization (provider key
